# payesh — سورس دفتر دیجیتال وکیل
پروژه Kotlin / Jetpack Compose بر پایه فایل payesh_Fixed، با مدیریت واقعی پرونده و ابلاغ، دریافت ثنا، تطبیق مستند، پیگیری و پیش‌نویس، OCR فارسی آفلاین و رابط راست‌به‌چپ.

## بیلد در GitHub
1. ZIP را استخراج کنید؛ **محتویات داخل آن** را در ریشه مخزن قرار دهید، نه خود فایل ZIP یا یک پوشه اضافه.
2. پوشه مخفی `.github`، فایل‌های `gradlew` و `gradle/wrapper/gradle-wrapper.jar` باید همراه سورس باشند.
3. در برگه Actions، گردش **Android build** را اجرا کنید. گردش **Source safety** نیز آزمون استخراج و هش فایل‌های باینری را کنترل می‌کند.
4. از بخش Artifacts، `payesh-APK-and-reports` را دریافت کنید. APK پوشه debug قابل نصب برای آزمون است؛ release عادی بدون امضای انتشار است.
5. گردش **Android device tests** آزمون رابط روی شبیه‌ساز را اجرا می‌کند. رمز و حساب واقعی ثنا در CI استفاده نمی‌شود.

## انتشار با امضای شما
در Settings → Secrets and variables → Actions، چهار secret به نام‌های `KEYSTORE_BASE64`، `STORE_PASSWORD`، `KEY_ALIAS` و `KEY_PASSWORD` تعریف کنید. گردش دستی **Signed release (manual)** خروجی APK و AAB امضاشده می‌سازد. کلید را داخل مخزن یا ZIP قرار ندهید و نسخه پشتیبان امن از آن نگه دارید. هیچ انتشار خودکار در فروشگاه انجام نمی‌شود.

## اجرای محلی
- JDK 17، Android SDK 36 و Build Tools 36.0.0، Node.js 20 یا جدیدتر.
- Gradle Wrapper نسخه 8.13 و هش توزیع همراه پروژه است.
- `local.properties` با مسیر SDK خودتان بسازید یا `ANDROID_HOME` را تعیین کنید.
- ویندوز: `powershell -File scripts/validate.ps1`
- لینوکس/macOS: `bash scripts/validate.sh`
- آزمون دستگاه: `./gradlew connectedDebugAndroidTest`
- حداقل Android 8 (API 26). نام بسته: `com.payesh.app`.
- وابستگی‌ها از Google Maven، Maven Central و برای Tesseract4Android از JitPack دریافت می‌شوند. روی شبکه‌ای که این مخازن در دسترس نیستند، از CI گیت‌هاب استفاده کنید؛ TLS را غیرفعال نکنید.

## مسیر استفاده
1. قفل صفحه دستگاه را تنظیم کنید؛ ورود برنامه با همان احراز هویت واقعی انجام می‌شود.
2. «دریافت و تطبیق ثنا» را باز و ورود ثنا را شخصاً تکمیل کنید.
3. فهرست ابلاغیه یا اطلاع‌رسانی پرونده را باز و دریافت را بزنید. دریافت پیوسته از صفحه فعلی تا پایان فهرست شناخته‌شده است؛ فیلترهای ثنا پابرجا هستند.
4. در فهرست‌های بومی برنامه، جست‌وجو و جزئیات، منبع و نتیجه تطبیق را ببینید. فقط بخش ورود/دریافت WebView است، نه کل رابط برنامه.
5. فهرست ابلاغ ممکن است شماره پرونده نداشته باشد. ارتباط از ارجاع صریح در گردش پرونده یا سند بازبینی‌شده به دست می‌آید، نه از حدس.
6. در پیگیری، پیش‌نویس را بسازید، متن و موعد را بازبینی و ذخیره کنید. «انجام‌شده» نیازمند یادداشت/رسید است و با «ابلاغ را بررسی کردم» فرق دارد.
7. از ابزارها، PDF/تصویر را وارد، OCR را بازبینی، موعد و فرصت مشروط بسازید و پشتیبان رمزدار بگیرید.

## محدوده قابل اتکا
جزئیات و محدودیت‌ها در [ردیابی نیازمندی‌ها](docs/REQUIREMENTS.fa.md)، [امنیت](docs/SECURITY.fa.md) و [اعتبارسنجی](docs/VALIDATION.fa.md) آمده است. پروژه خود را وابسته یا مورد تأیید قوه قضاییه معرفی نمی‌کند. قواعد حقوقی متن مکالمه، قانون رسمی تلقی نشده‌اند. دریافت همه قالب‌های ثنا، تاریخ دقیق اجرای کار پس‌زمینه، صحت OCR و نبود مطلق خطا تضمین‌پذیر نیست؛ خطا یا پوشش ناقص به‌صراحت گزارش می‌شود.

## ساختار
- `domain/`: شناسه، استخراج، صفحه‌بندی، تطبیق، مواعد و پیشنهاد اقدام؛ آزمون‌های JVM.
- `data/Vault.kt`: پایگاه محلی رمزگذاری‌شده، ادغام تراکنشی و پشتیبان.
- `web/` و `assets/sana/`: نشست WebView و آداپتورهای DOM محدود به دامنه رسمی.
- `documents/`: PDF، OCR فارسی/انگلیسی و آماده‌سازی ضمائم.
- `ui/`: صفحات Compose، طراحی فارسی و تقویم شمسی.
- `tests/web/`: آزمون ساختارهای استخراج با داده مصنوعی.
- `app/schemas/`: طرح پایگاه Room برای بررسی و توسعه مهاجرت‌ها.

داده نمونه واقعیِ کاربر، رمز، کوکی، کلید API، کلید انتشار، فایل نصب و مسیر اختصاصی رایانه در بسته سورس قرار نمی‌گیرند. پایگاه مرجع پیوست اولیه صرفاً مطالب عمومی مرجع را دارد و با داده دفتر مخلوط نمی‌شود.
